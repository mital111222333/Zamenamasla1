# Система учёта замены масла — мультитенантная версия

Один Telegram-бот и один сайт обслуживают **несколько независимых точек
замены масла**. У каждой точки — свой логин/пароль, своя база клиентов,
своя история, своя рассылка. Ты управляешь списком точек через отдельную
платформенную админку.

## Роли

- **Платформенный админ** (ты) — заходит на `/admin`, создаёт новые точки,
  включает/выключает их. Не видит клиентских данных ни одной точки.
- **Точка замены масла** — заходит на `/` под своим логином/паролем, видит
  и редактирует **только свою** базу. Технически это гарантируется на
  уровне каждого запроса к базе данных (`shop_id`), а не только интерфейсом.

## Изоляция данных — как это устроено

Каждый клиент, машина, история и рассылка помечены `shop_id`. Госномер
уникален **в рамках одной точки**, а не во всей системе — то есть у двух
разных точек вполне могут быть разные клиенты с одинаковым номером, и они
никогда не пересекутся. Каждый API-запрос на сайте берёт `shop_id` из
сессии залогиненной точки — обойти это, поменяв что-то в адресной строке,
нельзя.

## Первый запуск после обновления

Если ты уже пользовался более ранней версией (с одной точкой) — при первом
запуске обновлённого кода:
- Все твои существующие клиенты/машины автоматически получают `shop_id=1`
  (ничего не теряется).
- Точка №1 автоматически получает логин/пароль из старых переменных
  `SITE_USERNAME` / `SITE_PASSWORD` (если они были заданы) — можешь сразу
  входить ими же на `/`.
- Создаётся отдельный платформенный админ-аккаунт из переменных
  `PLATFORM_ADMIN_USERNAME` / `PLATFORM_ADMIN_PASSWORD`.
- Если какие-то из этих переменных не заданы — пароли сгенерируются
  автоматически и **один раз выведутся в логи Railway** (вкладка
  Deployments → последний деплой → Logs). Сохрани их сразу, второй раз
  показаны не будут.

## Настройка

Переменные окружения (Railway → Variables):

```
BOT_TOKEN=токен_от_BotFather
BOT_USERNAME=username_бота_без_собаки
ADMIN_TELEGRAM_ID=твой_telegram_id      # для команд /add /find /broadcast — только у точки №1

PLATFORM_ADMIN_USERNAME=admin           # логин платформенного админа (по умолчанию "admin")
PLATFORM_ADMIN_PASSWORD=надёжный_пароль

SITE_USERNAME=логин_точки_1             # логин/пароль ТВОЕЙ собственной точки (была "точка 1" в старой версии)
SITE_PASSWORD=надёжный_пароль
SHOP_NAME=MITAL Andijon
SHOP_PHONE=+998901112233
SHOP_ADDRESS=Андижан, ул. ...
SHOP_HOURS=Ежедневно 9:00–19:00
SHOP_LAT=40.7821                         # необязательно, для карты в боте
SHOP_LON=72.3442

SECRET_KEY=любая_длинная_случайная_строка   # для входа по сессиям — без неё все сессии слетают при каждом рестарте
DB_PATH=/data/oil_bot.db                 # путь на подключённый Railway Volume (см. ниже)
PUBLIC_URL=https://твой-сайт.up.railway.app
ANPR_WEBHOOK_TOKEN=...                    # больше не используется напрямую — см. раздел про табло ниже
```

Railway Volume (постоянный диск) обязателен, иначе база стирается при
каждом передеплое — см. раздел про Volume в истории проекта, если ещё не
подключал: создать Volume → mount path `/data` → `DB_PATH=/data/oil_bot.db`.

## Как добавить новую точку

1. Зайди на `https://твой-сайт.../admin` под платформенным логином.
2. Заполни название точки, придумай логин (пароль можно оставить пустым —
   сгенерируется автоматически и покажется один раз на экране, сразу
   сохрани).
3. Готово — эти логин/пароль отдаёшь владельцу точки. Он заходит на
   `https://твой-сайт.../` (без каких-либо параметров в адресе — сайт сам
   понимает, какая это точка, по логину) и пользуется тем же интерфейсом:
   внесение замены, база, рассылка, экспорт.

Новую точку заводить через открытую форму регистрации нельзя — только ты
как платформенный админ создаёшь аккаунты. Это осознанно: доступ выдаётся,
а не раздаётся самостоятельно.

## Экспорт / резервная копия (по требованию точки)

На вкладке «⬇️ Экспорт» у каждой точки — кнопка «Скачать резервную копию»:
отдаёт один JSON-файл со всеми клиентами, машинами и историей именно этой
точки. Пригодится для переноса на другой сервер или как страховка.

## Бот — что изменилось

- Клиент переходит по персональной ссылке → бот сам понимает, к какой
  точке его привязать (это закодировано в самой ссылке) — никаких
  дополнительных действий от клиента не требуется.
- Кнопка «ℹ️ О пункте» в боте показывает данные именно ТОЙ точки, к которой
  привязан конкретный клиент (адрес/телефон/часы каждой точки задаются при
  её создании в `/admin`).
- Команды `/add`, `/find`, `/broadcast` прямо в Telegram по-прежнему
  работают, но **только для точки №1** (той, что управляется через
  `ADMIN_TELEGRAM_ID`) — это сохранённый старый способ работы для твоей
  собственной точки. Все остальные, новые точки работают только через
  сайт со своим логином — им не нужно ничего знать про команды бота.

## Табло у входа (ANPR-камера) — теперь у каждой точки своя ссылка

У каждой точки автоматически создаётся свой секретный токен для табло.
Точка сама увидит нужные адреса на сайте (или узнай их у меня, если нужно
показать конкретной точке, куда вписывать URL в настройках камеры):

```
Вебхук камеры:  https://твой-сайт.../api/anpr/<токен_точки>?plate={номер}
Экран/табло:    https://твой-сайт.../display/<токен_точки>
```

Токен каждой точки уникален — камера/табло одной точки физически не может
показать или зафиксировать данные другой.

## Рассылка объявлений и акций

Не изменилось по сути — просто теперь у каждой точки своя собственная
рассылка, своя история рассылок и свои получатели (клиенты именно этой
точки). С сайта — вкладка «📢 Рассылка». Из бота — команда `/broadcast`,
доступна только точке №1.

## Возможные доработки на будущее

- Экран «Настройки» для точки — самостоятельно редактировать своё
  название/телефон/адрес/часы работы, без обращения к платформенному
  админу.
- Возможность у платформенного админа временно «войти» в кабинет
  конкретной точки для помощи с настройкой (сейчас это отдельные,
  несвязанные роли).
- Простая статистика на `/admin` — сколько всего клиентов/замен по всем
  точкам за месяц.
